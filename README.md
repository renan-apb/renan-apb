# Hi, I’m Renan Andrade

**Flutter Engineer · Mobile Accessibility · Cross-platform Product Development**

I build maintainable Flutter products for iOS and Android, with accessibility treated as an engineering requirement from the beginning—not a final compliance pass.

My production work includes accessible fitness, learning, advocacy, and IoT experiences for U.S.-based clients. Most of that code is proprietary, so the public repositories below demonstrate the engineering practices I use professionally without reproducing client implementations.

## What I work with

- **Mobile:** Flutter, Dart, iOS, Android
- **Accessibility:** WCAG, Flutter Semantics, VoiceOver, TalkBack, focus management, dynamic announcements, text scaling
- **Architecture:** BLoC, Riverpod, dependency injection, Clean Architecture
- **Services:** Firebase, REST APIs, Strapi, analytics
- **Delivery:** spec-driven development, GitHub, pull requests, CI/CD, Azure pipelines, App Store and Play Store builds
- **Collaboration:** direct communication with U.S.-based clients in English, working across Product, Design, QA, and Engineering

## Selected product work

- **Theodoor by Doorbotics** — contributing to a Flutter controller for an accessible IoT door-opening system involving BLE and Wi-Fi experiences. Theodoor was recognized by the CTA Foundation’s CES 2027 Eureka Park Accessibility Contest.
- **aXis for AdaptX** — accessible fitness discovery with onboarding, Firebase, geolocation, search, filters, favorites, and cross-platform delivery.
- **Rocky Mountain ADA Center** — an accessible Flutter learning experience with dynamic Strapi content, reusable course components, authentication, and assistive-technology-focused navigation.
- **Accessible advocacy learning product** — current work using reusable Flutter foundations, implementation-ready specifications, and accessibility acceptance criteria. Client-sensitive details are intentionally omitted.

## Public engineering work

### [Flutter Accessibility Lab](https://github.com/renan-apb/flutter-accessibility-lab)

A specification-led collection of production-oriented Flutter accessibility patterns, including semantic structure, focus management, accessible validation, live regions, screen-reader testing, and automated accessibility guidelines.

## How I work

1. Translate product and accessibility requirements into explicit behaviors and acceptance criteria.
2. Build maintainable Flutter features around clear state and architecture boundaries.
3. Validate with automated tests, VoiceOver, TalkBack, and platform inspection tools.
4. Document decisions so accessibility remains maintainable across the team.

## Background

Before software engineering, I worked as a physiotherapist and completed a master’s degree in Rehabilitation Sciences. That background continues to shape how I identify barriers, understand users, and build technology that works for more people.
